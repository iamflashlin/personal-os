## Goal
The user wants every mail, not only the last 14 days, summarised once ("全部邮件"; if the
month's budget would run out, stop and say so).
- **IMAP:** after the new mail, each sync reads up to 200 older messages, newest first,
  until the history is done. The cursor keeps `backfill_below` and `backfill_done`. A
  cursor from before this change starts history below what it has read, and mail that was
  already stored is recognised by its id. A message the server refuses in history becomes
  a note and never blocks. A renumbered mailbox restarts history.
- **Summaries:** all synced mail, newest first. The monthly budget still stops a run before
  a call that would exceed it, and the UI shows 「本月 AI 预算已用完」.

## Acceptance (runnable)
- `uv run pytest tests/hub/test_email.py tests/hub/test_summaries.py tests/hub/test_today.py -q`:
  - history comes after new mail, newest first, until done;
  - a long history is read in batches;
  - an old cursor starts history below what it read;
  - a refused history message becomes a note;
  - a renumbered mailbox restarts history;
  - old mail is summarised, newest first;
  - pending counts all synced mail.
- `uv run python scripts/verify/hub.py history` exits 0. It uses the real Hub, a fake IMAP
  server and FakeProvider, and checks that:
  - the first sync reads today's mail and mail 45, 120 and 400 days old;
  - all 4 get one summary each, with 4 model calls;
  - a second sync stores nothing twice and summarises nothing twice.
- `uv run python scripts/verify/hub.py email` and `summaries` still pass.
- `uv run python -m tools.check` exits 0.
- After merge, on the user's mailbox, `live-after.log` records before/after numbers for
  stored email items, summary rows by status, and the month's model calls and spend.
  Pass when:
  - stored mail grows past the first-sync window;
  - no Message-ID is stored twice;
  - new model calls = new `ok` + failed attempts (nothing summarised twice);
  - zero `bad_output` at the output-token cap.

  A large mailbox needs hours at about 200 mails per sync, so the log says "in progress,
  N stored" until history is done.
