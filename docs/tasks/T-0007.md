## Goal
VISION direction 3. A separate agent process that:
- connects out to the Hub, and survives Hub restarts with jittered backoff;
- stops when its token is revoked;
- executes only whitelisted actions (open_url, open_folder_in_editor), each with
  verify(), at most once per idempotency_key, and only through the DesktopController
  interface.

## Context / inputs
- Contracts and the protocol come from T-0006, and the design from ADR 0014.
- The agent keeps no durable state except its token in keyring (HANDOFF §4.6).
- Pairing uses stdlib urllib, because httpx is dev-only.
- The platform controller is loaded lazily, so this card runs without the Windows adapter.

## Out of scope
WindowsAdapter and the real GUI (T-0008), screenshots, launch_app, tray icon, auto-start.

## Acceptance (runnable)
- `uv run pytest tests/desktop_agent -q` passes on ubuntu and windows CI, covering:
  - the same key executes once, both sequentially and concurrently; the cache is bounded;
  - an unknown action, bad params or a timeout gives failed;
  - a missing `code` CLI gives needs_user and starts no process; a path with cmd
    metacharacters gives failed;
  - backoff stays within bounds; REGISTRY keys == ACTION_SPECS keys;
  - the loop against an in-process uvicorn Hub:
    - pair, welcome, heartbeat, and an action round trip;
    - a replay executes once;
    - a Hub restart reconnects;
    - revoke makes run_agent return auth_rejected with no further connects;
    - 4409 gives replaced.
- `uv run python -m apps.desktop_agent --help` exits 0.
- `uv run python scripts/verify/agent_link.py` exits 0 with real Hub and agent processes:
  - the agent comes online within 15 s;
  - a Hub restart reconnects within 35 s;
  - revoke makes the agent exit 3 within 10 s, and a second start also exits 3;
  - the keyring entry under a unique service name is deleted afterwards;
  - no window is opened.
- `uv run python -m tools.check` exits 0.

## Errors & lessons

- ADR 0014 D1 said keyring is Windows-only, but pyright on the Ubuntu runner must resolve
  the import. keyring is pure Python, so it is installed everywhere (ADR 0015 §7).
- The first loop draft sent late results on the socket they started on; after a reconnect
  they would have been dropped. Results now go through the agent's current connection, or
  wait for the next one (`test_a_result_finished_while_offline_is_delivered_after_reconnecting`).
