## Goal
The user found the site unreachable: the Hub only ran while a terminal window was open.
Make it always available on this PC without manual steps:
- it starts in the background when the user logs in to Windows, with no window;
- if it crashes it starts again by itself;
- it runs from its own copy of the code (`D:\dev\personal-os-run`) and keeps its data in
  `D:\dev\personal-os-data`, so development (branch switches, test databases) never
  disturbs it;
- one command updates it, one command removes it completely.

## Out of scope
- Starting the desktop agent automatically (it is not paired yet).
- Reaching the Hub from the phone (S4, needs Tailscale and authentication first).

## Acceptance (runnable)
- (user step, pending) `powershell -File scripts/run/install-always-on.ps1` creates the runtime copy, builds
  the web page there, and registers a per-user scheduled task (no administrator rights)
  that starts at logon; the Hub answers on http://127.0.0.1:8765 within 60 s.
- (user step, pending) `uv run python scripts/verify/always_on.py --expect-task` exits 0 after
  the user ran the installer: `/health` is ok, the page loads,
  the data dir is `D:\dev\personal-os-data`, the code comes from the runtime copy; after
  the Hub process is killed it is back within 60 s; the scheduled task exists with a logon
  trigger.
- `powershell -File scripts/run/uninstall-always-on.ps1` stops it and removes the task
  (the runtime copy and data stay unless `-RemoveCopy` is given).
- 未验证: a real logoff/logon or reboot (the user's next login proves it).
- `uv run python -m tools.check` exits 0.
