## Goal
On 2026-11-11 the user ran the installer while the assistant's working copy was on an
unmerged branch. `-Ref HEAD` deployed that branch for ~10 minutes. Now `-Ref` defaults to
`origin/main`, which is fetched first; passing `-Ref <commit>` still works.

The live T-0029 check (`.evidence/T-0029/always-on.log`) also failed: a repetition on the
logon trigger only starts at the next logon, so after an install `NextRunTime` was empty and
a killed supervisor stayed down. The watchdog is now a separate time trigger, firing every
5 minutes from install time onward.

## Acceptance (runnable)
- The script parses (PowerShell parser).
- `install-always-on.ps1 -PrepareOnly -CopyDir D:\dev-cache\t0032-copy -DataDir
  D:\dev-cache\t0032-data`, run from a feature branch, prepares the copy at origin/main's
  commit, not at the branch's.
- `uv run python -m tools.check` exits 0.
- After the user reinstalls: `uv run python scripts/verify/always_on.py --expect-task
  --watchdog` exits 0. A time trigger repeats PT5M with no end, `NextRunTime` is set, and a
  killed supervisor comes back within 6 minutes.
