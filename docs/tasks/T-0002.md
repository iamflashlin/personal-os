## Goal
V0.1 S1 part 2: manage the task hierarchy and workspaces over HTTP, with every write
recorded in a redacted audit log.

## Context / inputs
HANDOFF §4.3 (Goal/Project/Task with status, due date, dependencies, execution mode
Delegate/Collaborate/Human-led; Workspace = URLs, folders, apps bound to task/project;
AuditEvent), §4.6 (redaction before write), §3 item 7 (idempotency keys).

## Out of scope
Sessions/snapshots (S3), planner (S5), Evidence & completion (S6), auth (S2/S8 — single
local owner from config for now, but every row carries `owner_id`).

## Acceptance (runnable)
- `uv run pytest tests/hub -q` passes, covering for each entity: create / get / list / update / delete; 404 on unknown id; 422 on invalid payload; optimistic `version` conflict returns 409
- Same `Idempotency-Key` header on a repeated POST returns the original resource and creates no duplicate (test)
- Every write creates one AuditEvent (actor, action, entity, result); a test asserts a payload containing `token=abc123` / `Authorization: Bearer ...` is stored redacted
- Task with `execution_mode=human_led` is the default for tasks tagged `course:CIS` (test)
- Request/response models live in `packages/contracts`; OpenAPI schema exported to `packages/contracts/openapi.json` by `tools/export_openapi.py`; a test fails if the committed file is stale
- `uv run python scripts/verify/hub.py crud` creates a goal→project→task→workspace against the real running Hub over HTTP and reads it back; exits 0
- `uv run python -m tools.check` exits 0
