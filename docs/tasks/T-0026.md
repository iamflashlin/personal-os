## Goal
After T-0025 went live, 32 of the user's real mails failed with `bad_output` (empty
content or broken JSON), each at exactly 600 output tokens. A live diagnosis with a fake
email reproduced it: on harder inputs DeepSeek reasons on its own (`reasoning_content`)
and uses up the whole `max_tokens`, so no answer is left. All the failing mails contained
links, and prompt v2 asked for "links or codes they must use". The 未验证 item
"reasoning tokens on by default" from ADR 0025 was real.

## Acceptance (runnable)
- `uv run pytest tests/hub/test_models.py tests/hub/test_summaries.py tests/hub/test_today.py -q`:
  - DeepSeek requests carry `thinking: {"type": "disabled"}` unless `reasoning=True`;
  - long links (≥ 40 characters after `http(s)://`) are replaced by 「[链接]」 before
    sending, and short ones stay;
  - a v1 summary and an older-prompt failure are redone once, and a good v2 summary is
    not;
  - a failure is stamped with its prompt version, so the same prompt never loops on it;
  - 今日 uses any v2+ title.
- A live diagnosis is saved in `.evidence/T-0026/diag.log` (fake email, < US$0.002). On
  the same link-heavy mail:
  - v2 with thinking on: `finish=length`, 600 tokens, empty content;
  - v3 with thinking on: still overflows;
  - v3 with thinking off: `finish=stop`, 91 tokens, a correct answer.
- `uv run python -m tools.check` exits 0.
- After merge and `update-hub.ps1`: the user's mails that failed are redone, and the
  failure count drops. The outcome is recorded in `.evidence/T-0026/live-after.log`.
