## Goal
The school half of the user's morning brief (VISION, ADR 0012). The user gave their
school's Canvas address (kept out of the repository; it is personal). With a personal access token the user creates in Canvas,
the Hub syncs, in the background:
- active courses;
- assignments, with due date, points, link, and whether they were submitted, graded,
  missing or late;
- announcements from the last 30 days.

The token is a credential (T-0011). The Canvas address is not secret, so integrations get
a small non-secret `config`.

## Out of scope
- Connecting the real account (the user does that in the 连接 page; see the summary for
  the steps). Grades history, discussions, files, submitting anything (P3, never here).

## Acceptance (runnable)
- `uv run pytest tests/hub/test_canvas.py tests/hub/test_integrations.py -q` passes against
  a local stand-in Canvas server, covering: pagination via `Link: rel="next"`; assignment
  and announcement items with their fields; re-sync updates without duplicates; 401 gives a
  clear "token refused" error; the token is only ever sent to the configured host (a
  redirect or `next` link to another host is refused); the token is in no response, table,
  log, job or audit row; the Canvas address is validated (https, or http only on loopback).
- `uv run python scripts/verify/hub.py canvas` exits 0 against the real Hub with the
  stand-in Canvas server and a throwaway Credential Manager entry.
- `pnpm run typecheck`, `pnpm run test`, `uv run python scripts/verify/web.py`, and
  `uv run python -m tools.check` exit 0; the 连接 page can add a Canvas connection.
- 未验证 until the user connects: the real school Canvas API (token creation may
  be disabled by the school). Spike: the user creates a token and connects it (≤ 15 min).
