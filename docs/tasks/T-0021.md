## Goal
The Hub's one door to a language model (HANDOFF §4.4), first used by the AI email
summary the user asked for (T-0022, T-0023). Business code calls
`models.service.ModelClient.call_json(prompt, variables, OutputType)` and gets back a
validated Pydantic object.

Behind that call:
- a `ModelProvider` protocol;
- a DeepSeek adapter on stdlib `urllib` (OpenAI-compatible JSON mode, no SDK, no new
  dependency);
- a deterministic `FakeProvider`;
- versioned prompts in `prompts/*.vN.toml`;
- a `model_call` row for every call (vendor, model, tokens, cost, latency, prompt version);
- prices with a dated source, always charged at peak rates;
- a US$10 monthly cap, checked before every call against an upper-bound estimate.

The key is read only through `credentials.service.reveal`, under credential name
`deepseek`.

## Out of scope
- Email summaries, job wiring, HTTP routes and the web UI (T-0022, T-0023).
- Streaming, tool calls, a second vendor, and off-peak prices in the bill.

## Acceptance (runnable)
- `uv run pytest tests/hub/test_models.py -q` passes, covering:
  - **Requests:** against a local OpenAI-compatible stub (`tests/hub/fake_openai.py`), the
    DeepSeek adapter sends `response_format=json_object`, `max_tokens`, the model name and
    a Bearer key. It reads `prompt_cache_hit_tokens`, `prompt_cache_miss_tokens` and
    `completion_tokens`, and tolerates leading blank keep-alive lines.
  - **Errors:**
    - 401 → `ModelUnavailable("key_rejected")`;
    - 402 → `no_balance`;
    - 429 → `rate_limited`;
    - 500 and timeouts → `ModelFailed(retryable=True)`;
    - empty or non-JSON content, and output that fails the schema → `bad_output`,
      retryable, with its billed tokens recorded.
  - **Records:** every attempt writes one `model_call` row with vendor, model, purpose,
    ref, prompt name/version/sha, tokens, `cost_micro_usd`, `latency_ms` and status. The
    row is written as `reserved` at its estimate before the request and updated after.
  - **Cost:**
    - it uses peak prices from `pricing.py` (source and date are in the file) and is
      rounded up;
    - an unpriced model is refused;
    - the estimate is ≥ the stub's reported usage cost for ASCII, Chinese and mixed
      bodies.
  - **Budget:**
    - with spent + estimate > cap, no HTTP request is made (the stub's counter is
      unchanged) and no row is written;
    - the month is the UTC calendar month;
    - reserved rows and maybe-billed error rows count towards it.
  - **Key:**
    - no key → `ModelUnavailable("no_key")` without a request;
    - the key is revealed once per client;
    - the key is in no row, audit detail, exception text or log record;
    - no prompt or email text is stored in `model_call`.
  - **FakeProvider:** it is deterministic, and its `[fake:…]` markers raise the matching
    errors.
- `uv run python scripts/verify/models.py` exits 0. On a fresh SQLite under
  `data/verify/`, with real migrations and a 127.0.0.1 stub, it shows:
  - a successful call and its row;
  - 401, 429, 500 and bad-JSON handling;
  - budget refusal before any request;
  - the key absent from every byte of `hub.sqlite*` and from stdout.
- `uv run python scripts/verify/models.py --live` runs only when the user has entered the
  key and agreed to the run:
  - it reads the key from Credential Manager (`personal-os-hub`, `local:deepseek`) and
    never prints it;
  - it makes one call with a fixed tiny prompt and no personal data;
  - pass: valid JSON, usage parsed, cost ≤ US$0.001, estimate ≥ actual;
  - without a key it exits 1 with 「先在连接页输入 DeepSeek key」.
- `uv run python -m tools.check` exits 0, with `apps.hub.models` in both import-linter
  contracts.
- 未验证 until the live run: the model id `deepseek-flash`, JSON mode, the usage field
  names, whether reasoning tokens are on by default, and whether api.deepseek.com is
  reachable from this PC. Spike: the `--live` run above (≤ 15 min, < US$0.001).
