## Goal
The foundation that the email and school (Canvas) integrations need, and that the user
asked to build first (2026-11-10: "先打地基，后功能"). The Hub can:
- run background work outside a web request;
- retry failed work with backoff, and give up after a limit;
- run a piece of work on a fixed interval (e.g. "sync mail every 15 minutes");
- never create two jobs for the same idempotency key;
- recover after a crash or restart without losing queued work.

## Context / inputs
- HANDOFF §4.3: the Job table has status, retry count, idempotency key, next run time.
- HANDOFF §5: SQLite job table + worker of about a hundred lines; Temporal and DBOS only
  when there are several machines.
- ADR 0014: one uvicorn worker, so one in-process job worker is enough.
- Delivery is **at least once**: a job interrupted by a crash runs again. Handlers must be
  idempotent (unlike desktop actions, which are at most once).

## Out of scope
- Real integrations (email, Canvas) and their credentials (T-0011, T-0012).
- Cron expressions, priorities, several workers, a jobs page in the web UI.

## Acceptance (runnable)
- `uv run pytest tests/hub/test_jobs.py tests/hub/test_job_worker.py -q` passes, covering:
  - enqueue then run: status queued → running → succeeded, one attempt;
  - a failing handler is retried with growing delays, then succeeds;
  - after `max_attempts` failures the job is `dead` with the last error; retrying a dead
    job via `POST /jobs/{id}/retry` queues it again; retrying a non-dead job is 409;
  - an unknown kind goes straight to `dead` without retries;
  - the same idempotency key enqueues one job; the same key with a different payload
    is refused;
  - a job left `running` by a crash is queued again at startup;
  - an interval schedule enqueues one job per slot, coalesces missed slots after downtime,
    and creating the same schedule twice changes nothing;
  - the worker stops cleanly with the Hub; owner scoping; one audit event per write; a
    secret in a payload or error is redacted in the audit log.
- `uv run python scripts/verify/hub.py jobs` exits 0 against the real Hub process:
  a job runs; a 1-second schedule produces jobs with distinct slot keys; after a Hub
  restart the schedule continues without a duplicate slot.
- `uv run python -m tools.export_openapi --check` and `uv run python -m tools.check` exit 0.
